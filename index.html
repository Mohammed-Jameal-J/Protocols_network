CONCEPTUAL FRAMEWORK
OSI 7-Layer Model
Open Systems Interconnection

Enna Idhu — Definition

OSI Model oru conceptual framework — network communication-ah 7 layers-a divide pannuthu, ovvoru layer-kum specific job irukku. Namba ippo varaikkum paartha ella protocol-um (HTTP, TCP, IP, MAC) — ellame indha 7 layers-la oru place-la than "fit" aagum.

7 Layers — Bottom to Top

  1. Layer 1 — Physical: Actual cables, WiFi radio signals, electrical pulses. Data 0s and 1s-a travel pannurathu.
  2. Layer 2 — Data Link: MAC address use panni, same local network-la devices identify pannurathu (switches).
  3. Layer 3 — Network: IP address use panni, routing pannurathu (routers) — IP, ICMP idhu layer-la than.
  4. Layer 4 — Transport: TCP/UDP — reliable delivery, port numbers, data segments-a break pannurathu.
  5. Layer 5 — Session: Rendu device-oda connection/session-ah manage panni, open-a vachirukurathu.
  6. Layer 6 — Presentation: Data format, encryption/decryption (SSL/TLS idhu layer-la fit aagum), compression.
  7. Layer 7 — Application: User-facing protocols — HTTP, FTP, DNS, SSH, IMAP ellam idhu layer-la than.
Real World: Postal system mathiri nenachukonga — letter content (Application), envelope-la sealed/coded (Presentation), delivery tracking (Session), package split panni multiple trucks-la (Transport), address vachi route pannurathu (Network), local delivery van driver house find pannurathu (Data Link), actual road/vehicle (Physical).

PHYSICAL LAYOUT
Network Topologies
Star, Bus, Ring, Mesh

Enna Idhu — Definition

Topology nu solradhu, devices ellam eppadi physically/logically arrange pannirukanga nu sollura layout. Idhu decide pannuthu network eppadi perform pannum, edhavadhu device fail aana enna aagum nu.

Types

  1. Star: Ella devices um oru central hub/switch/router kitta connect aagirukum. Ippo miga romba common — office/home WiFi ellam idhu than.
  2. Bus: Ella devices um oru single shared cable-la connect aagirukum. Old style, andha cable break aana whole network down aagidum.
  3. Ring: Devices circular loop-la connect aagi, data device-to-device pass aagum, last device first device kitta thirumbi varum.
  4. Mesh: Ovvoru device um ella other devices kittayum direct connect aagirukum. Highly redundant — oru path fail aanalum vera path irukkum. Cost adhigam, aana critical infrastructure (data centers, military networks) ku use pannuvaanga.
  5. Hybrid: Mele sonna types-la rendu/moondru combine pannina setup — real world-la periya companies ipdi than use pannuvaanga.
Real World: Un veetu WiFi router — phone, laptop, TV ellam router (hub) kitta than direct connect aagirukum, devices-ku devices direct connect aagaathu — idhu Star topology.

HTTP
HyperText Transfer Protocol

Enna Idhu

Browser oda webpage ah kekkurathukku (request pannurathukku) use pannura basic rule book than HTTP. Nee browser la oru website address type panna, browser andha website oda server kitta "enakku indha page kaatu" nu HTTP moolam kekkum, server andha page anupputhum.

Eppadi Work Aagum

  1. Browser (client) server ku HTTP Request anupputhu — "GET /index.html" mathiri.
  2. Server request ah process pannitu HTTP Response anupputhu — HTML, CSS, images.
  3. Response oda status code irukkum — 200 (OK), 404 (Not Found), 500 (Server Error) mathiri.
  4. HTTP stateless — ovvoru request um independent, server ku previous request nyabagam irukathu.
Real World: Nee google.com type pannumbothu, browser HTTP request anupputhu, Google server search page anupputhu — adhu than HTTP in action.

HTTPS
HTTP Secure (HTTP + SSL/TLS)

Enna Idhu

HTTPS na basic ah HTTP than, aana SSL/TLS encryption layer add panniruppanga. Adhaan data ellam encrypt panni anuppudhu, so middle la yaaravadhu data ah steal panna try pannalum, adhu scramble aana text ah than kaanum, padikka mudiyathu.

Eppadi Work Aagum

  1. Browser and server, TLS Handshake moolam "secure channel" onnu create pannikuranga (SSL/TLS section paaru).
  2. Andha secure channel vazhiyaa than actual HTTP data (login, card details) anuppuranga.
  3. Browser address bar la padlock icon kaanum — "idhu safe" nu indicate pannurathukku.
Real World: Online banking, Amazon checkout, Gmail login — ella sensitive site um HTTPS than use pannum. URL la "https://" nu irundha andha site secure nu artham.

SSL / TLS
Secure Sockets Layer / Transport Layer Security

Enna Idhu

Original image la idhu miss aayirundhuchu, so ithu mukkiyama add pannirukom! SSL um TLS um encryption protocols — HTTPS, email, VPN ellam idha use pannuthan secure ah irukanga.

SSL um TLS um Same-aa? — Clear Difference

Illai, literally same illai — aana pesumbodhu ellarum "SSL" nu than solvaanga, artham "TLS" than.

  • SSL (versions 1.0/2.0/3.0) — original protocol, ella version-um deprecated ippo, security vulnerabilities (eg: POODLE attack) irukku, use pannakoodathu.
  • TLS (versions 1.0/1.1/1.2/1.3) — SSL-oda successor. TLS 1.0/1.1 um deprecated. Ippo ella modern website-um TLS 1.2 or TLS 1.3 than use pannuthu.
  • Adhunala: "SSL certificate" nu solraanga na, real-a andha certificate TLS-ku than use aaguthu — "SSL" nu peru mattum industry habit-la stay aayiduchu.

Port Address — Idhu Fixed Port Illai!

SSL/TLS oru separate port illai — idhu oru encryption layer, existing protocol mele (top-la) wrap pannikkum. Adhunala port number depend aaguthu, eppadi (edhukku) TLS use pannuthu nu:

443HTTPS — normal secure web browsing
465 / 587SMTPS — secure email sending
993IMAPS — secure email fetching (IMAP + TLS)
995POP3S — secure email download
636LDAPS — secure directory access

Eppadi Work Aagum — TLS Handshake

  1. Client Hello: Browser server kitta "hi, enakku secure connection venum" nu sollum, adhoda supported encryption methods list.
  2. Server Hello + Certificate: Server thanoda TLS certificate anuppum (idhu server oda identity proof, trusted authority sign panniruppanga).
  3. Key Exchange: Rendu side um sernthu oru shared secret key create pannikuranga (public-key cryptography use panni).
  4. Encrypted Session Start: Ippo andha shared key vachu, ella data um encrypt/decrypt pannuranga — idhu than "secure connection".
Real World: Nee net banking la login pannumbothu certificate check aagum (padlock icon click panni paaru — "Issued by DigiCert" mathiri kaanum). Adhu than TLS certificate — port 443 vazhiyaa than idhu ella work aaguthu.

File Transfer Protocol

Enna Idhu

Files ah oru computer la irundhu vera server ku upload pannurathukkum, download pannurathukkum use pannura protocol. Website hosting panravanga, developers ellam files ah server ku transfer panna FTP use pannuvanga.

Eppadi Work Aagum

  1. FTP client software (FileZilla mathiri) use panni server kitta connect aaganum — username/password vechi.
  2. Connect aana pinnadi, files ah drag-and-drop panni upload/download panlaam.
  3. Rendu channels use aagum — command channel (port 21) instructions ku, data channel (port 20) actual file transfer ku.
  4. ⚠️ Plain FTP encrypt aagathu — password um data um plain text ah than poidum. Adhunala FTPS or SFTP (secure versions) recommend pannuvanga.
Real World: Web developer oru website build pannitu, andha HTML/CSS files ah hosting server ku FTP moolam upload pannuvaan.

DATA LINK LAYER
MAC Address & ARP
Media Access Control / Address Resolution Protocol

Enna Idhu -- Definition

MAC Address -- ovvoru network card (NIC)-kum manufacturer factory-la burn panni kudukkura unique hardware ID (eg: 00:1A:2B:3C:4D:5E). IP address maadhiri illama, idhu physical address -- normal-a maaraadhu.

ARP -- oru device-ku IP address theriyum, aana actual-a data anuppanum na, andha IP address-oda MAC address venum (same network-la mattum). ARP than andha IP-ku correspond aagira MAC address-ah find pannikodukkum.

Eppadi Work Aagum

  1. Device A, IP 192.168.1.10-ku data anuppanum, aana MAC address theriyaadhu.
  2. Device A network-la ella devices-kum broadcast pannum -- "192.168.1.10 kitta MAC address enna?"
  3. Andha IP-oda owner (Device B) mattum reply pannum -- "en MAC address idhu" nu.
  4. Device A idha ARP cache/table-la save pannikkum, adutha thadava kekka theva illa.
Real World: Un WiFi-la rendu laptops IP address vechi pesukum-bodhu, actual-a data deliver aaguradhu MAC address vazhiya than -- adha ARP than andha lookup panni kodukkum.
ARP: BROADCAST REQUEST -> DIRECT REPLY
TRANSPORT LAYER CONCEPT
Ports & Sockets
How Multiple Apps Share One IP Address

Enna Idhu — Definition

IP address oru building address mathiri nenachukonga — building-la mattum solli letter deliver panna mudiyaathu, exact apartment/flat number venum. Network la andha "apartment number" than Port — 0 to 65535 varaikkum number, edhavadhu specific app/service data-ah receive pannanum nu identify pannuthu.

Socket = IP address + Port number + Protocol (TCP/UDP) — idhu oru specific "conversation"-ah uniquely identify pannuthu.

Port Ranges

  1. Well-Known Ports (0–1023): Standard services ku reserved — HTTP 80, HTTPS 443, FTP 21, SSH 22, DNS 53 (idha ella already paathom).
  2. Registered Ports (1024–49151): Specific applications register pannikuvanga (eg: MySQL 3306).
  3. Ephemeral/Dynamic Ports (49152–65535): Client side temporary-a use pannum, connection open pannumbodhu automatic-a assign aagum.
Real World: Nee browser-la 3 tabs open panni, same website (google.com:443) 3-um visit panna, ovvoru tab-kum different ephemeral source port assign aagum (eg: 52001, 52002, 52003) — adhunala server ovvoru tab-oda conversation-ah separate-a track panna mudiyum, destination port (443) same-a irundhalum.
ONE IP, MANY PORTS = MANY SERVICES
TRANSPORT LAYER
TCP
Transmission Control Protocol

Enna Idhu

TCP oru reliable, connection-oriented protocol — data anuppurathukku munnadi rendu devices um oru "connection" establish panniduvanga, apparam data packets order la, loss illama pogum nu guarantee pannum.

Eppadi Work Aagum — 3-Way Handshake

  1. SYN: Client server kitta "connect aaganuma?" nu kekkum.
  2. SYN-ACK: Server "sari, connect aagalam" nu reply pannum.
  3. ACK: Client confirm pannum — connection establish aayiduchu.
  4. Ippo data transfer start aagum — packets order la poganum, edhavadhu packet miss aana, athai TCP marupadiyum anuppum.
Real World: File download pannumbothu, oru single byte kooda miss aagakoodathu illa na file corrupt aagidum — adhunala TCP use pannuvanga (email, web browsing, file transfer ellame TCP than).

IP
Internet Protocol

Enna Idhu

Internet la irukura ovvoru device kum oru unique address kudukkurathu than IP. Idhu illama data ah enga anuppanum nu theriyaamal poidum. IP address oru device oda "veedu number" mathiri nu nenachukonga.

Eppadi Work Aagum

  1. Ovvoru device kum (phone, laptop, router) oru IP address assign aagum.
  2. Data packets small pieces ah split aagi, ovvoru packet-leyum source and destination IP address irukkum.
  3. Routers indha IP address ah paathu, correct path la packet ah anuppuranga (routing).
  4. IPv4 (192.168.1.1 mathiri, 4 billion addresses) old standard; IPv6 (adhigam addresses ku) puthusa vandhurukku.
Real World: Nee "what is my IP" nu google search panna, un device oda public IP address kaatum — adhu than internet la un "identity".

ADDRESSING CONCEPT
Private IP vs Public IP
Two Types of IP Address Everyone Has

Definition

Private IP — un home/office network inside-la mattum use aagura address. Idhu router assign pannum (DHCP moolam), and idhu internet-la route aagaathu — velila irundhu direct-a idha reach pannave mudiyaathu. Range: 192.168.x.x, 10.x.x.x, 172.16.x.x – 172.31.x.x.

Public IP — un ISP (Airtel, Jio, BSNL) kudukkura address, idhu whole internet-le unique. Velila irukkura ella server um, un network-ah identify pannurathukku indha address-ah than use pannum.

Eppadi Rendum Connect Aagum — NAT

  1. Un veedu-la irukkura phone, laptop, smart TV — ellathukkum router private IP kudukkum (192.168.1.x mathiri) — DHCP process-la paathom illa.
  2. Indha devices ella internet-ku poganum na, router oda NAT (Network Address Translation) feature, ella private IP-yayum ore public IP-ku "translate" pannum.
  3. Internet-la irukkura server (eg: youtube.com), un router oda public IP-ah than paakkum — inside-la irukkura individual private IP-a paakkave maattaanga.
  4. Response vandhu, router adha correct device-ku (correct private IP-ku) route pannum.

Real World Example

Un veetu WiFi-la phone 192.168.1.5, laptop 192.168.1.6 nu private IP irukkum. Aana rendu devices um internet-ku poganum na, ISP kudutha ore public IP (eg: 49.207.x.x) than velila kaanpikkum. "What is my IP" nu Google search panna kidaikkura address — adhu un public IP, un phone settings-la irukkura WiFi IP — adhu private IP.

❓ "Private IP Share Pannina System Hack Aaguma?"

Correct Answer: Illai, direct-a hack aagaathu. Private IP address (192.168.x.x mathiri) internet-la route aagaathu — adhunala velila irukkura yaaravadhu, un private IP number-ah mattum vechi, direct-a un network-ku vandhu connect panna mudiyaathu. Adhu un veetu inside-oda address than, outside world-ku andha address "meaning" edhume illa.

Aana idhu safe nu artham illa — real risk enga irukku nu paakalam:

  • Same WiFi/network-la irundha: Coffee shop WiFi mathiri public network-la, un private IP-ah yaaravadhu therinjukittu, andha network inside-le attack panna try pannalam (file sharing vulnerabilities, weak passwords) — idhu than real risk.
  • Public IP + open ports: Un router-la "port forwarding" set pannirundha, and andha port-la vulnerable service run aaguthu na, attacker un public IP-ah scan panni exploit panna try pannalam. Idhu than real danger — private IP alla, public IP + weak security combination.
  • Malware / phishing: Miga adhikam hacks nadakuradhu IP address theriyum-nu alla — weak password, phishing link click panradhu, outdated software moolam than.
Chinna summary: Un private IP (192.168.1.5 mathiri) yaaravadhu kitta sonna, adhu ore oru information mattum than — adhai vechi mattum yaarum un system-ah "hack" panna mudiyaathu. Real security depend aaguthu firewall, strong passwords, updated software, and public-facing services correct-a secure pannirukkiya nu.

NETWORK LAYER
Subnetting / CIDR
Classless Inter-Domain Routing

Enna Idhu — Definition

Subnetting — oru periya network-ah, chinna chinna sub-networks-a divide pannurathu — organization, security, and traffic efficiency-ku. CIDR notation (eg: 192.168.1.0/24) — network address-oda "/24" enna solluthu na, first 24 bits network portion-ku, remaining 8 bits host (device) portion-ku.

Eppadi Work Aagum

  1. /24 = subnet mask 255.255.255.0 — total 256 addresses (0-255) kidaikkum.
  2. Adhula rendu addresses reserve aagirukum — first one network address, last one broadcast address — so 254 usable host addresses than kidaikkum.
  3. /24 vida chinna number (eg: /28) — chinna subnet, konjam devices mattum; periya number (eg: /16) — periya subnet, adhigam devices.
Real World: Oru company office-la, Sales team-ku 192.168.1.0/24 subnet, Engineering team-ku 192.168.2.0/24 subnet kudukalaam — rendu department-oda traffic separate-a irukkum, security um improve aagum.

ADDRESSING STANDARD
IPv4 vs IPv6
Two Generations of IP Addressing

Enna Idhu — Definition

IPv4 — original addressing system, 1980s-la irundhu use aaguthu. 32-bit address, dotted-decimal format-la irukkum (eg: 192.168.1.1). Total ~4.3 billion addresses mattum than possible — internet grow aana pinnadi, idhu run out aayiduchu!

IPv6 — puthu generation addressing system, IPv4 shortage-ah solve panna vandhadhu. 128-bit address, hexadecimal colon-format-la irukkum (eg: 2001:0db8:85a3::8a2e:0370:7334). Total addresses — 340 undecillion (340 followed by 36 zeros) — practically never run out aagathu.

Key Differences

ConfigManual / DHCPAuto (SLAAC) / DHCPv6

Eppadi Transition Aaguthu

  1. Internet ellame ore neraththil IPv6-ku maaraadhu — adhunala Dual Stack use pannuvaanga: device-ku IPv4 and IPv6 address rendum kudukkuvaanga.
  2. Website/server IPv6 support pannaathu na, IPv4-la fallback aagum.
  3. Slowly slowly, ISPs, websites, devices ellame IPv6-ku migrate pannikittu varaanga.
Real World: India-la Jio network largely IPv6-la than run aaguthu (mobile data). Un phone settings-la "IPv6" nu kidaikkum, adhu already active-a irukkalam. Google, Facebook, YouTube — ivanga ella sites-um IPv4 and IPv6 rendum support pannuvaanga (dual stack).

NETWORK MANAGEMENT
NAT Deep-Dive, VLANs & Routing Protocols
NAT Types · Virtual LANs · OSPF/BGP

NAT — Types (Deep-Dive)

Namba basic NAT already paartha (private IP → public IP). Aana NAT-la 3 types irukku:

  • Static NAT: Oru private IP, permanent-a oru specific public IP-ku map aagum (1-to-1). Server hosting-ku use pannuvaanga.
  • Dynamic NAT: Private IPs, oru pool of public IPs-la irundhu, available-a irukkura edhavadhu onnu vechi map aagum.
  • PAT (Port Address Translation) / NAT Overload: Namba veetu router use pannura type — multiple private IPs, ore public IP-ah share pannuvaanga, aana ovvoru device-kum different port number assign pannuvaanga so router traffic-ah correctly track panna mudiyum.

VLAN — Virtual LAN

VLAN, ore physical switch-la connect pannirukura devices-ah, logically vera vera networks-ah separate pannuthu — physically vera cable venaam. Idhu security-ku and traffic management-ku romba use aagum.

Routing Protocols — OSPF vs BGP

  • OSPF (Open Shortest Path First): Oru single organization-oda internal network-la (multiple routers irundhaal), best/fastest path-ah automatic-a find pannurathukku use aagum — Interior Gateway Protocol.
  • BGP (Border Gateway Protocol): Vera vera networks/ISPs-ku idaiyeye (between) routing information exchange panna use aagum — idhu than literally whole internet-ah connect pannura protocol. Exterior Gateway Protocol.
Real World: Un company internal-a multiple office branches-ah OSPF vechi connect pannalaam. Aana un data, Chennai-la irundhu US server-ku poganum na, andha path-ah decide pannurathu — different ISPs-oda BGP routers than andha "route" decide pannuvaanga, globally.

UDP
User Datagram Protocol

Enna Idhu

UDP TCP oda opposite mathiri — connectionless, handshake edhume panna maatanga, straight ah data anupputtu iruppanga. Speed than mukkiyam, konjam packet miss aanalum problem illa.

Eppadi Work Aagum

  1. Handshake illame directly data packets (datagrams) anuppuranga.
  2. Delivery guarantee illa — packet lost aana, marupadiyum anuppa maatanga.
  3. Idhunala TCP ah vida rendu, moondru madangu fast ah irukkum.
Real World: Video call la (Zoom, Google Meet) oru frame miss aanalum paravaayillai, delay aagakoodathu — adhunala video/voice calls, online gaming, live streaming ellam UDP than use pannum.

ADDRESSING TYPE
Unicast / Multicast / Broadcast
How Data Gets Addressed to Devices

Enna Idhu — Definition

Data anuppumbodhu, adhu evlavu devices ku pogum nu decide pannura 3 types irukku:

  1. Unicast: Oru sender → oru specific receiver. Web browsing, most HTTP traffic ellame idhu than — sender to ore oru destination.
  2. Broadcast: Oru sender → network-la irukkura ella devices-kum. DHCP Discover, ARP request idhu than use pannuthu — "yaaravadhu reply pannunga" nu ellarukkum anuppuvaanga.
  3. Multicast: Oru sender → specific subscribed group mattum (special IP range 224.0.0.0 – 239.255.255.255 use pannuvaanga). Idhu unicast-um broadcast-um-oda middle ground.
Real World: Netflix video stream — ovvoru user-kum separate individual stream (Unicast). IPTV/live TV multicast group-ku mattum stream aagum (Multicast — subscribed devices mattum receive pannum). DHCP request pannumbodhu "IP venum" nu whole network-ku shout pannuvom (Broadcast).

PACKET SIZE LIMIT
MTU & Packet Fragmentation
Maximum Transmission Unit

Enna Idhu — Definition

MTU — oru network link-la, oru single packet-ah split pannaama anuppa mudiyara maximum size (Ethernet-ku typical-a 1500 bytes). Packet idha vida periya irundha, andha link-la travel panna mudiyaathu — split pannanum (fragmentation) illena drop aagidum.

Eppadi Work Aagum

  1. Sender packet create pannum, andha packet size, path-la irukkura ella links-oda MTU-ah vida periya irundha, problem varum.
  2. Router andha packet-ah chinna pieces-a fragment pannum (allow pannirundha), or packet-la "Don't Fragment" flag set aayirundha, router andha packet-ah drop pannitu, sender-ku "fragmentation needed" error anuppum.
  3. Idha vechi than Path MTU Discovery work aaguthu — sender gradually correct packet size figure out pannikuvaan.
Real World: VPN use pannumbodhu, encryption overhead-ala effective MTU kammi aagum — configure sariya pannaama irundha, konjam websites open aagaama irukkalam (fragmentation issues). Idhu than common VPN troubleshooting reason.

NETWORK LAYER · DIAGNOSTICS
ICMP / Ping / Traceroute
Internet Control Message Protocol

Enna Idhu — Definition

ICMP — regular data transfer-ku alla, diagnostic and error reporting-ku use aagura protocol. "Idhu host reachable-a?", "Enna problem irundhuchu?" nu sollurathu ICMP oda vela.

Ping — Eppadi Work Aagum

  1. Nee ping google.com type panna, un computer ICMP Echo Request anuppum.
  2. Target server, ICMP Echo Reply vechi respond pannum.
  3. Round-trip time (latency) measure aagum — "google.com is up, 24ms" mathiri.

Traceroute — Eppadi Work Aagum

Traceroute, un data destination-ku pogum vaikkula ovvoru router (hop)-um kaattum — TTL (Time To Live) value-ah 1, 2, 3 nu increase panni, ovvoru router-layum "TTL expired" error anuppa vechi, path-ah map pannuthu.

Real World: Internet slow-a irundhaa, traceroute run panni, exact-a enga (edhu router-la) delay aaguthu nu find panna mudiyum — troubleshooting-ku romba use aagum.
PING = IS IT ALIVE? TRACEROUTE = WHAT'S THE PATH?

DNS
Domain Name System

Enna Idhu

Computers ku domain names (google.com) puriyathu, IP address than puriyum. DNS oru "phonebook" mathiri — domain name kudutha, correspond aagira IP address ah kodukkum.

Eppadi Work Aagum

  1. Nee browser la "google.com" type panna, indha name ku IP address theriyathu.
  2. Browser oru DNS resolver kitta kekkum "google.com oda IP enna?" nu.
  3. Resolver, Root DNS → TLD (.com) server → Authoritative server nu step by step lookup pannum.
  4. IP address kidaichathum (eg: 142.250.183.14), browser andha IP kitta connect aagum.
Real World: Phone la contact name click panna number dial aaguthu illa? DNS um adhe maadhiri than — name type panna, andha peruku pinnadi irukura "number" (IP) ah find pannikum.
NAME → LOOKUP → IP → SITE
DNS SECURITY EXTENSION
DNSSEC
Domain Name System Security Extensions

Enna Idhu — Definition

Sonna maadhiri DNS oru "phonebook" — aana problem enna na, normal DNS-la, response fake-a irundhalum browser-ku theriyaathu! Yaaravadhu attacker fake DNS response anuppi, un "bank.com" ah wrong IP-ku redirect panniralam (idhai DNS spoofing / cache poisoning nu solvom). DNSSEC idha thadukka vandha security layer — DNS records-ku digital signature add pannuthu, so response genuine-a nu verify panna mudiyum.

Eppadi Work Aagum

  1. Domain owner, DNS records-ah private key vechi cryptographically sign pannuvaanga.
  2. Resolver DNS response vaangumbodhu, andha signature-ah public key vechi verify pannum.
  3. Signature match aana mattum than resolver andha response-ah trust pannum — illena, "invalid, reject pannu" nu drop pannidum.
  4. Idhu oru chain of trust — Root DNS → .com (TLD) → domain, ovvoru level-layum sign pannirukum, so end-to-end verify aagum.

Real World

DNSSEC illaama, public WiFi-la irukkura attacker, un DNS request-ah intercept panni fake IP kudukka try pannalam (Man-in-the-Middle attack). DNSSEC irundha, andha fake response signature match aagaathu, browser andha response-ah reject pannidum. Banks, government sites (.gov), and major domains ellam DNSSEC use pannuvaanga extra protection-ku.

Note: DNSSEC data-ah encrypt pannaadhu (adhu TLS oda vela) — adhu response genuine-a irundhaal mattum verify pannum. Rendu-layum sernthu use panna sollradhu than best practice.
SIGNED DNS RESPONSE → VERIFY → TRUST OR REJECT

Firewalls & VPNs
Traffic Filtering & Encrypted Tunneling — In Detail

Firewall — Definition

Firewall, trusted internal network-kum, untrusted internet-kum idaiyeye nikkura oru "gatekeeper" — rules vechi, traffic-ah allow pannuma illa block pannuma nu decide pannuthu.

  • Packet-Filtering Firewall: Basic — IP address, port number vechi mattum allow/block pannum.
  • Stateful Firewall: Connection-oda "state" track pannum — already established connection-oda traffic mattum allow pannum.
  • Next-Gen Firewall (NGFW): Deep packet inspection, application-level filtering, intrusion detection ellam sernthu irukkum.
  • WAF (Web Application Firewall): Namba security section-la paartha maadhiri, specifically website attacks (SQLi, XSS) thadukkum.

VPN — Definition

VPN, un device-kkum oru VPN server-kkum idaiyeye oru encrypted tunnel create pannum. Un real IP hide aagum, traffic ellam encrypted-a poi, VPN server-oda IP-la than "exit" aagum.

  1. Un device VPN app vechi VPN server-ku connect aagum (encrypted).
  2. Un ella internet traffic-um indha tunnel vazhiyaa than pogum — un ISP-kooda andha data padikka mudiyaadhu.
  3. VPN server, un traffic-ah real destination-ku forward pannum — destination server-ku, VPN server-oda IP than theriyum.
Real World: Remote employees, company internal systems access panna VPN use pannuvaanga — office network inside-la irukkura maadhiri secure-a connect aaguvaanga, veetu-la irundhe vela pannalum.

Proxy Servers
Forward Proxy vs Reverse Proxy

Enna Idhu — Definition

Proxy — client-kum destination server-kum idaiyele nikkura oru intermediary server. Rendu types irukku:

  1. Forward Proxy: Client(s)-oda front-la nikkum — client-oda identity-ah internet-ku hide pannum. Companies employees-oda internet access control panna, content filter panna use pannuvaanga.
  2. Reverse Proxy: Server(s)-oda front-la nikkum — server-oda identity-ah internet-ku irundhu hide pannum. Load balancing, caching, SSL termination, extra security layer ku use pannuvaanga (eg: Nginx, Cloudflare).
Real World: Office network-la social media block aaguthu na, adhu Forward Proxy than pannuthu. Cloudflare oru website-oda front-la nikkumbodhu — visitors real backend server IP-ah pakka mudiyaathu, adhu Reverse Proxy.
FORWARD = HIDES CLIENT · REVERSE = HIDES SERVER

Load Balancers & CDNs
Traffic Distribution & Content Delivery

Load Balancer — Definition

Popular website-ku millions of users vandhaa, oru single server handle panna mudiyaathu. Load Balancer, incoming traffic-ah multiple backend servers-ku evenly distribute pannum, so oru server mattum overload aagaathu.

  1. Client request Load Balancer-ku varum.
  2. LB, "eppo idha route pannanum" nu decide pannum (Round Robin — order-la kodukkum, or Least Connections — kammi busy-a irukkura server-ku kodukkum).
  3. Selected backend server request handle panni response kodukkum, LB vazhiyaa client-ku poi serum.
  4. Oru server down aana kooda, LB automatic-a andha server-ah skip panni, remaining servers-ku traffic route pannum — high availability.

CDN — Definition

CDN (Content Delivery Network), world-wide different locations-la edge servers vechi, website-oda static content (images, videos, JS/CSS files)-ah cache pannum. User, origin server-ku (eg: US-la irukkum) pogaama, thanoda nearest edge server-la irundhe content vaanguvaan — romba fast.

Real World: Netflix/YouTube video stream panna, Chennai-la irukkura user, US-la irukkura origin server-ku connect aagaadhu — Chennai/Mumbai-la irukkura CDN edge server-la irundhe video varum. Amazon, high-traffic sale days-la (Big Billion Days) Load Balancer use panni, thousands of servers-ku traffic split pannum.

Bandwidth vs Latency vs Throughput
Three Different Speed Metrics

Enna Idhu — Definition

Moondrum "speed" nu solvom, aana different things:

  1. Bandwidth: Connection-oda maximum theoretical capacity — Mbps/Gbps la measure pannuvom. Highway-oda "how many lanes" nu nenachukonga.
  2. Latency: Data source-la irundhu destination-ku poi varakkum delay time — milliseconds (ms) la measure pannuvom. Oru car trip complete panna eduthukkura time mathiri.
  3. Throughput: Real-world-la actually transfer aagura data — congestion, packet loss, overhead ellam consider pannitu. Bandwidth-ah vida always kammi-a than irukkum practical-a.
Real World: Satellite internet — high bandwidth (100 Mbps) irundhalum, high latency (600ms+) irukkum, adhunala download fast-a irundhalum, online gaming lag aagum. Fiber broadband — bandwidth kammi-a irundhalum, low latency-ala calls/gaming smooth-a irukkum.

REST API
Representational State Transfer

Enna Idhu — Definition

REST oru protocol illai — idhu oru architecture style / set of rules, HTTP protocol-ku mele build pannirukira convention. "Resources" (data — users, products, orders) ah URLs moolam identify pannurom, and standard HTTP methods vechi andha resources-la operations pannurom.

GETData read panna (fetch)
POSTPuthu data create panna
PUT/PATCHIrukkura data update panna
DELETEData delete panna

"REST API Everywhere Pass Aaguthu" — Ipdi Solraanga, En?

Idhu than key point: REST enn'na oru programming language-oda alla, HTTP protocol-oda attached. HTTP ellaa OS, browser, mobile app, server language-layum universal-a support pannum. Adhunala:

  1. Django (REST Framework), FastAPI, Node/Express, Spring Boot — ivanga ella backend-um ultimate-a oru HTTP server than run pannuvaanga. Internal code Python-a, JavaScript-a, Java-va irundhalum, over-the-network level-la ellame same — HTTP request vandhu, HTTP response poguthu.
  2. Client (browser, mobile app, Postman, veru server) — backend Django-va, FastAPI-va nu kavalaippadaadhu. Adhukku theriyanum na "correct URL-ku correct HTTP method-la request anuppuna, JSON response kidaikkum" nu than.
  3. Idhuna, "contract" (agreement) HTTP request/response format-la than irukku — language-la illai. Adhunaala FastAPI-la build pannina REST API-ah, React app-um, Android app-um, Django app-um — ellame same-a call panna mudiyum.
  4. Django REST Framework — Django-la REST APIs easy-a build panna oru library. FastAPI — Python-la vega (fast) REST APIs build panna modern framework, automatic docs/validation kudukkum. Rendum ultimate-a same HTTP rules-ah than follow pannuvaanga — implementation style mattum vera.

Real World Example

Un banking app la balance check pannumbodhu, app GET /api/accounts/123/balance nu request anuppum. Backend Django-va, FastAPI-va irundhalum — response same JSON format-la than varum: {"balance": 45000}. Adhunala frontend team backend language maathinaalum, app-la edhume maathanum theva illa.

Key Takeaway: REST API "everywhere pass aaguthu" enna, adhu HTTP-oda universal nature-ah use pannuthu — DNS, TCP, IP ellam already universal-a work pannura maadhiri, REST-um andha same HTTP foundation mele than nikkuthu. Django-um FastAPI-um "language" mattum vera, "protocol" same.

MODERN SECURITY MODEL
Zero Trust Networking
"Never Trust, Always Verify"

Enna Idhu — Definition

Old model — "castle and moat": oru device company network inside-la irundha, automatic-a trust pannuvom. Zero Trust idha reject pannuthu — where request vandhaalum (inside office-layum irundhalum), every single request-ah verify pannanum than.

Core Principles

  1. Verify Explicitly: Ovvoru request-um, ovvoru time-um authenticate/authorize pannanum — one-time login-a trust pannaadhu.
  2. Least Privilege Access: User/device-ku evlavu access required, adhai mattum kudukkanum — extra access illama.
  3. Assume Breach: Network already compromise aayiruchu nu nenachukittu design pannanum — segment pannunga, encrypt pannunga, continuously monitor pannunga.
Real World: Employee office-la physically irundhu, office WiFi-la connect aayirundhalum, company app access panna MFA + device verification venum — "office-la irukkiye" nu automatic trust kudukka maattanga. Google, Microsoft ellam ippo Zero Trust model-ku maariduchanga.

Defense Guide

Website-ah Attackers Kitta Irundhu Eppadi Protect Pannurathu

Ippo namba paatha ella protocol/API knowledge-um use panni, real attacks-ah eppadi thadukkanum nu paakalam — Phishing, Brute Force, and Penetration Testing (idha epdi use pannanum) moondrayum detail-a paakalam.

Social Engineering Attack

Phishing

Attacker fake email/website vechi, real company mathiri nadichi, un password/card details-ah steal panna try pannuvaan (eg: fake "bank.com" login page).

  • DMARC / SPF / DKIM — un domain-oda email authentication set pannunga, spoofed emails block aagum.
  • HTTPS + valid certificate — users padlock icon paathu verify pannikkalam.
  • MFA / 2FA compulsory pannunga — password mattum theriyunda login aagaathu.
  • Lookalike domains (eg: bankk.com) monitor pannunga — brand protection tools use pannalam.
  • Employees/users-ku phishing awareness training kudunga — click pannuradhukku munnadi verify panna sollunga.
Credential Attack

Brute Force

Attacker automated tool vechi, login page-la thousands of password combinations try pannuvaan — correct password kidaikkum varaikkum guess pannuvaan.

  • Rate limiting — oru IP-la irundhu, oru time-ku eththana login attempts nu limit pannunga.
  • Account lockout — 5-6 wrong attempts-ku apparam account temporary-a lock pannunga.
  • CAPTCHA add pannunga — bots-ah block pannurathukku.
  • Strong password policy + MFA — password guess pannalum, second factor illama login aagaathu.
  • WAF (Web Application Firewall) use pannunga — suspicious traffic pattern automatic-a block aagum.
Proactive Defense

Penetration Testing

Idhu authorized, controlled attack — un own security team (or hired experts) real hacker mathiri, un website-ah test panni, vulnerabilities-ah real attacker kandupidikkura munnadi kandupidipparanga.

  • Idha legal permission vechi mattum pannanum — un own site-la mattum, illena unauthorized-a vera edhavadhu system-la panna illegal.
  • Industry standard: OWASP Top 10 vulnerabilities check pannuvaanga (SQL injection, XSS, broken auth, etc).
  • Regular ah (eg: every 6 months) pannunga — puthu vulnerabilities discover aagiyeye irukum.
  • Report-la kidaikkura issues-ah fix panni, marupadiyum test pannunga (re-test).

  1. 1
    URL type pannurathu
